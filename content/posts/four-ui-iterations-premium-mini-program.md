最后一版设计稿出来的时候，我第一次觉得：这不是一个「AI 味」的界面，而是一个有主张的产品。

但真正改变结果的，不是我换了一个更强的生成工具。最后一版用的还是 OpenDesign，真正的变量是我在它前面加了一层 Design DNA：我终于把「我想要什么样的审美」写成了工具能执行、也能检查的规则。

这是一套面向民办幼儿园的家园共育小程序。四版迭代里，我用了三种 AI 设计工具：Impeccable、[OpenDesign](https://github.com/nexu-io/open-design)，以及一个叫 [Design DNA](https://github.com/zanwei/design-dna) 的技能。整套流程是在 Claude Code 里串起来的：我负责判断，agent 负责采集、生成、审计和记录。

下面把过程完整拆开。

## 四版迭代

| 版本 | 时间 | 做了什么 | 结果 |
| --- | --- | --- | --- |
| V1 | 2026-03 | 产品设计原始稿 | 功能齐全，没有视觉主张 |
| V2 | 2026-10 | Impeccable 优化 | 规范了，但「一般」 |
| V3 | 2026-10 | OpenDesign 全量重设计 | 有设计感，但瓶颈是我 |
| V4 | 2026-11 | Design DNA + OpenDesign | 最终满意 |

![四版小程序 UI 对比：从产品原始稿到 Design DNA 最终版](/images/four-ui-versions.webp)

*截图：V1 / V3 / V4 为家长端首页，V2 为 Impeccable 优化后的成长页；头像与姓名均为示例数据。*

### V1：功能清单

第一版来自产品设计阶段。需求写得很全：今日在园、通知、接送、请假、成长记录、班级相册……每个功能都有页面。界面是典型的「功能清单」：橙色头部、八宫格入口、每个入口一种颜色，蓝色链接和橙色按钮混在一起。

它能把需求跑通，但没有任何视觉主张。把 logo 换成另一家幼儿园的，也完全成立。

### V2：Impeccable 把界面「修干净」了

第二版用 Impeccable 做优化。它帮我把 token 的执行修一致、修掉了间距和圆角的不一致、去掉了不少「AI 生成感」。规范度确实上来了，但我看着它，只能给出「一般」两个字的评价。

第二版的底子，是一套叫「Tender Cosmos（温柔宇宙）」的暖橙体系：胶囊按钮、大圆角、琥珀色阴影、暖色渐变。它不难看，但更像一个通用 SaaS 套了一层暖色皮肤。Impeccable 把这层皮修得很干净，却没有换掉它。

后来我想明白了：**在我的用法里，Impeccable 主要承担优化。** 它能在「已经有一个明确审美」的前提下做减法——去掉 AI 味、修掉不一致、补齐状态；但它不负责替我回答「这个产品应该长成什么样」。它的上限，是你给它的审美底色。

### V3：OpenDesign 放大了我的表达，也放大了我的空白

第三版换 OpenDesign。它比我想象的强得多：我把产品 brief 和设计系统交给它，它生成了 51 页全量界面（老师端 + 家长端）；后来又基于同一套布局换出星海蓝、星空蓝、小王子三套主题。版式、信息层级、插画、状态，都比第二版更像「设计过」。

但我依然不满意。问题不在工具，在我自己：我没有设计基础，说不出一套完整的美学定义。我能给它的只有「暖一点」「高级一点」「不要像后台系统」这种形容词。三套主题也说明了同一件事：它能做风格变体，却没有回答「哪一种风格属于这个产品」。

OpenDesign 把我模糊的表达放大成了一版完整的界面——**它放大了我的执行力，也放大了我的空白。**

### V4：先定义审美，再让工具执行

第四版，我先停下来，不再让工具「自由发挥」。我用 Design DNA 从一个现成的设计里提取了一整套美学规则：颜色、字体、间距、圆角、阴影、组件、动效，以及明确的禁止项。

具体做法是：先采集参考产品登录后的 24 屏真实界面，用 DOM 计算样式和整页截图拿到真实值；再让 Design DNA 输出结构化的 `dna.json`，由 agent 整理成给人看的 `DESIGN.md`；然后先做 5 页验证集（首页、接送、成长列表、请假表单、成长详情），确认这套规则在真实业务信息密度下成立；再铺到家长端 31 页和 10 个状态（空态、错误态、接送三态等）；最后让 OpenDesign 按同一份 DNA 重出。

这一版出来，我第一次觉得「对了」。不是因为它更花哨，而是因为它终于像一个有主张的产品：每一页都在同一条审美线上。

## DNA 到底定义了什么

Design DNA 不是截图集，也不是一份 mood board。它把「审美」拆成三个维度：

- **可测量的设计系统**：颜色、字体、间距、布局、形状、阴影、动效、组件；
- **可感知的设计风格**：气质、构图、图像、交互手感、品牌语气；
- **视觉特效**：Canvas、WebGL、3D、粒子、着色器这些特殊渲染。

前两个维度决定「看起来高不高级」，第三个维度决定「要不要用 WebGL」。大多数业务小程序其实不需要第三层。

这套 DNA 里，真正把界面从「一般」拉到「高级」的，是三个决定。

先看 V2 和 V4 落到规则上的差别：

| 维度 | V2 | V4 |
| --- | --- | --- |
| 色彩 | 暖橙渐变 + 琥珀阴影 | 暖纸底 + 深松绿 + 单一强调 |
| 标题 | 无衬线、靠字重 | 衬线 400、靠字号和留白 |
| 卡片 | 大圆角 + 阴影浮起 | 白面 + 1px 发丝线、无阴影 |
| 入口与标签 | 每个入口一种颜色、彩色胶囊 | 单一强调、行内高亮 |
| 布局 | 信息密集、入口多 | 一屏一焦点、低密度 |

下面三条，是这套 DNA 里最关键的决定。

### 1. 颜色：暖纸底 + 深松绿 + 单一强调

画布不是纯白，而是暖纸色 `#ECE6D7`；正文和主按钮不是黑色，而是深松绿 `#173220`；强调色只有一种，橙色只出现在角标、未读点、警告图标这些「提示层」。语义色也不另起一套鲜艳色相：success / error 从土色里取，warning 复用橙色，info 用低饱和灰蓝。

这条规则的作用不是「好看」，而是消除杂音：当所有页面共享同一个色温，界面会先显得「是一个整体」，然后才谈得上高级。

### 2. 字体：衬线标题 + 无衬线正文，标题永远 400

标题用 Instrument Serif + Noto Serif SC，400 字重，负字距；正文和控件用中性无衬线。标题不加粗，层级靠字号、留白和字距，而不是靠 weight。

中文排版还做了一个单独的决定：H1 30px / 行高 1.35，衬线正文 17px / 行高 1.8。西文的负字距不能直接套在中文方块字上，这一点如果不单独处理，衬线标题会在中文里显得挤。

### 3. 形体与层级：发丝线、无阴影、行内高亮、一屏一焦点

卡片是白面 + 1px 发丝线，没有阴影；页面靠明度差和留白分层，而不是靠「浮起来」。标签不做胶囊 chip，而是行内文字高亮：句子里的词背后刷一块鼠尾草绿（sage）或万寿菊黄（marigold）的底色，文字仍是正文色。一屏只放一个焦点块，内容集中在上 60%，下方留白。

这些规则看起来是细节，但它们共同决定了界面「像不像一个被设计过的产品」。阴影、渐变、彩色胶囊、每个入口一个颜色——这些是最容易让界面变成「AI 味模板」的东西。

![Design DNA 的三个关键决定：色彩、字体、形体与工具分工](/images/design-dna-rules.svg)

把这几条规则放在一起，大概是这样：

| 维度 | 规则 | 作用 |
| --- | --- | --- |
| 画布 | `#ECE6D7` 暖纸底 | 去掉纯白的冷感 |
| 主色 | `#173220` 深松绿 | 文字、主按钮、图标 |
| 强调 | 橙色仅提示层 | 保持单一强调 |
| 标题 | 衬线 400，30px / 1.35 | 编辑感，不靠加粗 |
| 正文 | 无衬线 400 / 600，13–16px；衬线长文 17px / 1.8 | 易读 |
| 卡片 | 白面 + 1px 发丝线，无阴影 | 靠明度分层 |
| 标签 | 行内高亮，不做胶囊 | 签名特征 |
| 布局 | 单列、一屏一焦点、24–32px 分区 | 低密度呼吸感 |
| 动效 | 150ms 按压，300ms 抽屉 | 克制 |

更重要的是，这些规则是可检查的。DNA 里带了颜色测量和 ΔE（色差）校验：不是「我觉得这个绿色差不多」，而是从参考界面里测出真实色值，生成后再用脚本比对。设计风格是主观的，但落到 token、字号、间距、圆角、对比度上，它可以被写成可验证的约束。最终 31 页全部通过：静态审计 0 error，H1 衬线 400/30px、390×844 无横向溢出。

这里还有一个容易被忽略的点：**参考产品不是每一处都值得抄。** 我采集的那款海外亲子 App，自己的底部文字链只有 18px 高、筛选胶囊只有 28px，低于 44px 的触控建议。我在 DNA 里把这条改掉了。它也没有中文界面，所以「中文用衬线还是无衬线」不是从参考里提取的规则，而是我自己定的决策。

规则可以迁移，身份必须重做。Logo、插画、照片、文案、独特构图，都是身份，不是规则。举个具体的例子：同一个行内高亮，在参考产品里用于情绪标签；在我们这里用于「已入园」「17:00 后接」这类业务状态。迁移的是「用底色标记句中关键信息」这条规则，不是它的文案和色彩身份。判断标准很简单：如果一套规则必须带上原产品的 logo、插画或文案才好看，那它就不是规则，是身份。

## 工具的正确分工

四版走完，我对这三种工具的分工有了很明确的判断：

- **Design DNA 负责定义**：从一个成熟设计里提取规则，输出结构化的 `dna.json`，再由 agent 整理成给人看的 `DESIGN.md`；它是审美的输入层。
- **OpenDesign 负责生成与铺量**：方向未定时用来发散，方向定了就按 DNA 执行。
- **Impeccable 负责收敛**：在真实仓库里按 token 契约做审计、把执行修一致、去掉 AI 味、补齐状态；它不定义审美，但能把执行拉到及格线以上。
- **人负责判断**：选哪个参考、哪些规则必须保留、什么算「好」、什么时候停。

一句话：**工具没有你的审美。** 它不会替你决定这个产品该长成什么样；审美必须由人提供，或者由一份已经被验证过的 DNA 提供。工具越强，这个前提越重要——因为它会把你的输入放大，包括你的空白。

第三版就是最好的例子。OpenDesign 已经非常强大了，但在我这个没有设计基础的后端手里，它只能按我粗糙的表达生成一版「有设计感但不够好」的界面。不是它不行，是我给它的输入不行。第四版换成 DNA 之后，同样的工具、同样的 brief 结构，输出质量完全不一样。

最终版也不是把手工版逐页重绘一遍。中间的 31 页手工稿证明了规则在每一页都成立；OpenDesign 再接同一份 DNA 重出一版，首页的数字层级更清楚，接送页的状态卡更像一个真正的产品，切换孩子的抽屉和固定底部操作条也补上了。DNA 保证「不跑偏」，OpenDesign 负责把这些规则铺满 31 页。但方向错了，DNA 只会让错误更一致；它保证一致性，不保证方向正确。

## 可复用清单

如果你也是没有设计基础的开发者，想把界面从「能用」推到「高级」，下面几条可以直接抄走：

1. **选一个审美在线的参考，而不是凭感觉描述。** 不要只凭第一眼：选一个你连续用了一周仍然觉得舒服的产品；或者让一个你认可审美的朋友给你三个候选，再按使用场景筛。场景接近比风格接近更重要。
2. **采集真实界面，不要靠印象。** 截图、DOM、计算样式、颜色测量；印象里的颜色和实际色值经常差很远。
3. **让工具把规则写下来。** 颜色、字体、字号、行高、间距、圆角、阴影、组件、动效、禁止项；能写成 token 的写成 token。
4. **先做 5 页验证集。** 首页、列表、表单、详情、空态；不要一上来铺 50 页。
5. **再铺全量。** 验证集成立后，让 OpenDesign 按同一份 DNA 生成；每页都要过机械审计（H1 衬线 400/30px、画布色、390×844 无横向溢出、占位文案、外链、衬线字重）。
6. **用 token / lint 守住一致性。** 硬编码色值、随手写的圆角、临时加的阴影，都会让 DNA 失效。
7. **规则可以迁移，身份必须重做。** 参考产品的 logo、插画、照片、文案、独特构图，都不要抄；你迁移的是比例、节奏、对比和约束。

如果把这套方法再压缩一下，「高级感」的具体来源大概是这些：

- **留白**：一屏一个焦点，下方敢留空；
- **单一强调色**：只在一个地方用力；
- **字体对比**：衬线标题 + 无衬线正文，标题不加粗；
- **低密度**：列表行高 56–64px，分区 24–32px；
- **发丝线**：用 1px 线而不是阴影分层；
- **克制动效**：150ms 按压、300ms 抽屉，不做无限循环；
- **统一语气**：空态文案不施压，错误提示说人话。

这套方法也有边界：管理后台、高密度表格、强实时操作台，不适合照搬「一屏一焦点」；DNA 也不是判断力的替代品，它只能保证「不跑偏」，不能保证「有创意」。这套具体规则也不是通用公式：暖纸底、衬线、低密度适合这个产品的气质，换一个产品，应该重新选参考、重新提取 DNA。

这套流程也不是零成本：采集、DNA、5 页验证、31 页审计，每一步都要花时间；它省掉的是反复返工，不是设计本身。另外，这是设计阶段的复盘，不是上线后的用户研究；最终版目前是设计稿，真实可用性和业务效果还要等上线验证。

但在一个人做产品、没有设计团队的场景里，它能把「我觉得差不多」变成「我知道为什么」。

## 最后

最后一版家长端设计稿有 31 页、10 个状态。它不是每一页都惊艳，但每一页都在同一条审美线上：暖纸底、松绿、衬线标题、发丝线、行内高亮、克制的橙色。对我来说，这就是「高级感」的真实来源。

![最终版接送页：衬线标题、行内高亮、发丝线、无卡片阴影](/images/final-ui-detail.webp)

不是天赋，也不是工具。

是把审美变成规则的能力。

如果你也在做一人产品，或者正卡在「工具很强，但做出来还是不对」的阶段，可以先停下来问自己一句：我到底想要什么样的审美？如果说不清，就先去找到它，把它写成规则，再让工具执行。
